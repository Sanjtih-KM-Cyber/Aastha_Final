## Gotchas
- Native app API URL is hard-coded to `https://aastha-final.onrender.com/api` (`client/src/services/api.ts`).
- Server refuses to start without `JWT_SECRET`, `SERVER_ENCRYPTION_KEY`, `MONGO_URI`.
- Encryption: server-side AES-GCM with `NEW_SERVER_ENCRYPTION_KEY` (primary) + `SERVER_ENCRYPTION_KEY` (fallback). Losing these = losing all chat/diary data.
- Committed APKs are stale (debug APK has zero native plugins); don't use them to judge behavior. They're now gitignored.
- Client `npx tsc --noEmit` shows 21 pre-existing errors (Q10); `npm run build` works because Vite doesn't type-check. Server `tsc` is clean — keep it that way.
- Payments: old payments made before Phase 0 have no Razorpay-order check; only new verifications use the hardened path. Legacy Pro users without `subscriptionExpiresAt` expire at `subscriptionDate + 30d`.
- Chat messages: **always go through `messageStore`**; never read `Chat.messages` directly (legacy backup only). Legacy `Chat` docs keep their old messages for rollback; drop them once prod shows `Chat.countDocuments({migratedAt:{$exists:false}})` = 0.
- Auth tokens: login JWTs carry `tv`; any token with a `purpose` claim is NOT a session. Log a user out everywhere with `$inc: { tokenVersion: 1 }`.
- Client chat cache lives in `localStorage` (`aastha_chat_cache_v1:<userId>`), cleared on logout — including auto-lock logout.
- Integration test scripts (in-memory MongoDB) were run from the session scratchpad, not committed; recreate under `server/tests/` in the Quality track.
- New LLM code must use `streamChat`/`completeChat` from `services/llm.ts` — never instantiate Groq/Gemini clients directly (remaining direct Gemini helpers are Phase 6 tech debt).
- Groq may retire model names in `MODEL_CHAINS`; the layer skips dead ones automatically, but watch logs for `[LLM] … model_gone` and update `AI_CHAT_MODELS` on Render.
- `user.facts` entries are now encrypted strings; always `decrypt()` when reading (legacy plaintext still decrypts as-is).
- Safety: `assessRisk()` runs on every message before any LLM; never put safety handling behind the brain/LLM. The safety prompt section must stay LAST in `buildCompanionPrompt`.
- Run `cd server && npm test` before deploying (first run downloads a MongoDB test binary into the user cache, once).
- PWA users keep the old bundle until the service worker updates (autoUpdate) — after deploying, an old tab may need one reload.
- Lite mode is a global `html.lite` class; don't add new per-component blur/animation checks — style normally and let the CSS rule turn effects off.
- Design rule: **glass only for floating controls** (header bar, composer, tab pill, FAB); content uses `md-surface-*` / `bg-md-*` tonal tokens. Never hard-code hex colours in new UI — use `md-*` so the palette follows the user's seed.
- framer-motion `y`/`x`/`scale` animations overwrite Tailwind `translate-*` — centre animated elements with a flex wrapper instead.
- To see the app locally: terminal 1 `cd server && npm run dev:sandbox`, terminal 2 `cd client && npm run dev` → http://localhost:3000, log in with the demo account from `server/dev/sandbox.ts`.
- The Web (`Person`): always use `detectiveService` / `upsertPerson`; never query `Person.name` directly (it's ciphertext). Lookups use `nameHash = blindIndex(name)`.
- YouTube: always call `searchYouTube()` (cache + quota breaker); never call the Data API directly.
- Privacy copy (landing FAQ, Features, PrivacyCenter) must stay true — update it whenever data handling changes.
- Clone Mode: never bypass `hasValidConsent()`; keep crisis → Aastha bypass; style must stay structured notes (never let a model write the clone system prompt from screenshot text).
- Chat text is rendered by `MiniMarkdown` — never `dangerouslySetInnerHTML`, and no regex lookbehind in client code (iOS < 16.4 crashes).
- Diary reset: never add an unverified wipe endpoint again; all diary-reset paths go through `diaryController.verify()` (shared lockout).
- GIFs: only the model's short phrase goes to GIPHY/Tenor; keep the `allowGifs` guard (no crisis/concern/clone/voice/sad) in `chatController`.
- Exported chats are parsed on the device; the server must never store the raw messages (only encrypted style notes).
- Voice-note audio must keep HTTP Range support (`audioController.getAudio`) or seeking breaks. Don't reintroduce springs on draggable windows — commit position + zero the drag motion value in the same frame.
- Brain secret is **opt-in**: until `BRAIN_SHARED_SECRET` is set, the Space stays open (logs a warning).
- Client now has `@types/react`: client `tsc` is 0 errors and CI enforces it. Keep it that way (don't add `// @ts-ignore` to silence new ones).
- Chat stream: add new server events in `chatController` as `{type:'…'}` and handle them in ChatView's `onEvent`; the hook treats only `{content}` without `type` as reply text.
- Offline writes go through `createOfflineQueue` (one entry per key, backoff, single-flight). Its `sync()` must `await` before any early return — otherwise the lock never clears (bug caught by Vitest).
- Time zones: check-ins, the memory "Today" line and mood insights use the user's own zone (`user.timeZone`, sent by the app in the chat body and as `?tz=` on `/users/reach-out` and `/data/moods/insights`; validated by `utils/timeZone.ts`; India until known). Use `dayKeyIn/hourIn/localAt` — never add fixed offsets. The free-message quota still resets at **IST** midnight for everyone (`utils/dailyReset.ts`) — that's a product rule, not a bug.
- Follow-ups / check-ins: never send outside `reachOutBlockedReason()`; a crisis sets `reachOut.lastCrisisAt` (48 h no check-ins). Phone app = local notifications from `GET /users/reach-out` (IDs 2001–2005); web = push from the cron.
- User voice notes are stored **encrypted** (`VoiceNote.encrypted`); read them with `readAudio()`, never `note.buffer` directly. Aastha's TTS notes are still plaintext wav (S11/R10 unchanged).
- Reactions: only ❤️ 😂 👍, only on the user's own assistant messages (`setReaction` checks `user` + `role`). Ids come from the `saved` SSE event — a reply has a temp id until then.
- Sentry: both sides are no-ops without a DSN. Any new `captureError/reportError` call goes through `utils/scrub.ts` automatically; never add `extra`/request bodies.
- Privacy Center now describes check-ins, reactions and your recordings — keep it true if those change.
- **Message quota is a rolling 24 h window** (`utils/dailyReset.ts`): it opens with the first counted message and refills 24 h later, server clock only (changing the phone's time/zone can't refill it). Every counter that "resets daily" (messages, voice notes, clone replies) shares that window. Bond points still use IST days.
- Reactions accept any single emoji (`isAllowedReaction`: one grapheme, pictographic only). Custom mood emojis reuse the same check.
- The Web: `role` (≈20 kinds) + `vibe` (8) are chosen by the AI; `verdict` is only kept for old app versions. A user correction sets `userEdited` and re-scans never overwrite it.
- **Legal:** Privacy Policy/Terms text lives in `client/src/legal/content.tsx` and must stay TRUE to the code. Material change → bump versions in BOTH `client/src/legal/legalInfo.ts` and `server/src/legal.ts` (users re-accept). Sign-up requires `acceptTerms: true` and age ≥ 18 (server). Account deletion keeps only `PaymentArchive` (8-year TTL).
- **No rollback past 2026-11-23 encryption:** older server builds cannot read `v2:` ciphertext or the encrypted profile fields. Once this version has run against a database, don't deploy an older build against it.
- **Sanctuary-only styling:** user colour and fonts must never reach the public pages. `usePublicTheme().style` overrides every `--md-*`, `--primary-color` and `--app-font` on the page wrapper. Fonts are set on `<html>` by `useSanctuaryFonts()` and removed when the Sanctuary unmounts. New public page → wrap it in `style={usePublicTheme().style}`.
- **Glass:** `.glass` = frosted panel (content); add `.glass-clear` for chrome that floats over scrolling content. Glass over a flat colour just looks grey — keep something behind it (chat aura / wallpaper). Don't put `backdrop-filter` on per-message elements (lags phones).
- **Portals + React events:** events inside a `createPortal` still bubble through the React tree to the component that rendered it. Guard handlers with `e.currentTarget.contains(e.target)` (see `MessageBubble`).
- **Encryption:** never compare ciphertexts and never query by an encrypted field — use a blind index (`blindIndexCandidates` + `$in` for lookups, `blindIndex` for writes). User `name/region/avatar/wallpaper/dateOfBirth` encrypt via schema setters, so `.lean()` reads return ciphertext: wrap them in `decrypt()` (no-op on plaintext). Don't add `maxlength` to encrypted fields (the validator sees ciphertext). A new plaintext field to migrate → add to `PLAIN_FIELDS` in `services/keyRotation.ts` and bump `PLAIN_FIELDS_VERSION`.
- **Time:** never use server-local or IST dates for user-facing "days". Use `utils/timeZone.ts` with `user.timeZone` (sent as the `_tz` query value on every API call). The message quota is a rolling 24 h window (time-zone independent).
- Fonts are self-hosted via `@fontsource-variable/*` (no Google Fonts) — changing `tailwind.config.js` fonts needs a dev-server restart. Fraunces uses the SOFT axis (`.font-serif` in index.css).
- Icons for navigation/tabs/window titles come from `design/icons.tsx` (Phosphor duotone). Lucide is still fine for small inline glyphs.
